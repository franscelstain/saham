# Group Semantics — LOCKED (Contract)

Dokumen ini adalah **Single Source of Truth** untuk *grouping* kandidat pada payload **PREOPEN (PLAN)**.

- Berlaku untuk semua policy yang bersifat **ranked** (`WEEKLY_SWING`, `POSITION_TRADE`, `DIVIDEND_SWING`, `INTRADAY_LIGHT`) kecuali policy yang secara eksplisit menyatakan override.
- **NO_TRADE** adalah *policy mode* (monitor-only) dan **bukan** bagian dari cut/ranking di dokumen ini (lihat bagian “NO_TRADE mode”).

Semua threshold **HARUS** direferensikan dari config/env (tidak boleh hardcode angka di dokumen lain atau code path lain).

---

## Normalisasi skor

- `score_total` (fraction, range [0..1])

Kontrak:
- Semua score yang dipakai untuk ranking/grouping harus sudah berada di range `[0..1]`.
- `score_total = 0` berarti **tidak ada kualitas sinyal yang bisa dipakai** untuk ranking.

---

## Candidate universe gate (anti-banjir)

Group semantics hanya masuk akal jika kandidat yang diproses **relevan** untuk policy.

Kontrak:
- Setiap policy **Wajib** mendefinisikan “Signal markers” (lihat `docs/watchlist/policy/*.md` bagian *Signal markers*).
- Ticker **dianggap relevan** jika memenuhi minimal 1 marker policy (mis. signal_code tertentu / flag breakout / momentum label / dsb).
- Jika ticker **tidak relevan**, maka default = `excluded` (tidak perlu masuk avoid/watch).

Tujuan:
- Mencegah bucket `watch_only`/`avoid` menjadi “daftar seluruh ticker pasar”.

---

## Cut rules (Option A) — Single Source of Truth (LOCKED)

Definisi:

- `S0` = score_total tertinggi pada kandidat yang **eligible untuk NEW ENTRY**.

Rumus:

- `top_cut = max(TOPPICK_MIN_SCORE, S0 - TOPPICK_SCORE_GAP)`

Implementasi wajib (config/env):

- `TOPPICK_MIN_SCORE` = `config('trade.watchlist.group_semantics.toppick_min_score')` (env: `WATCHLIST_TOPPICK_MIN_SCORE`)
- `TOPPICK_SCORE_GAP` = `config('trade.watchlist.group_semantics.toppick_score_gap')` (env: `WATCHLIST_TOPPICK_SCORE_GAP`)
- `SECONDARY_MIN_SCORE` = `config('trade.watchlist.group_semantics.secondary_min_score')` (env: `WATCHLIST_SECONDARY_MIN_SCORE`)
- `WATCH_ONLY_MIN_SCORE` = `config('trade.watchlist.group_semantics.watch_only_min_score')` (env: `WATCHLIST_WATCH_ONLY_MIN_SCORE`)

Larangan (anti-drift):

- Dilarang menulis ulang angka threshold di dokumen lain atau code path lain (mis. `TOPPICK_MIN_SCORE = <number>`).

Catatan penting (anti salah tafsir):
- `toppick_max` / cap jumlah item **tidak boleh** ikut memengaruhi `top_cut`. Cap hanya untuk *display/selection*, bukan untuk menentukan cutoff.

---

## Avoid semantics (tidak boleh jadi tong sampah)

`avoid` adalah bucket untuk ticker yang **relevan** tapi **tidak layak entry** (blocked/risky/invalid), sehingga user melihat “kenapa tidak boleh”.

Kontrak utama:
- `avoid` **tidak boleh** berisi ticker yang tidak relevan (no signal marker).
- `watch_only` **tidak boleh** berisi ticker dengan `score_total = 0`.

Untuk mencegah banjir, `avoid` memakai aturan tambahan berbasis config:

- `AVOID_REQUIRES_SIGNAL` = `config('trade.watchlist.group_semantics.avoid_requires_signal')` (env: `WATCHLIST_AVOID_REQUIRES_SIGNAL`)
- `AVOID_SIGNAL_MAX_AGE_DAYS` = `config('trade.watchlist.group_semantics.avoid_signal_max_age_days')` (env: `WATCHLIST_AVOID_SIGNAL_MAX_AGE_DAYS`)
- `AVOID_MIN_SCORE` = `config('trade.watchlist.group_semantics.avoid_min_score')` (env: `WATCHLIST_AVOID_MIN_SCORE`)

Semantik:
1) **Hard-block avoid**
   - Jika ticker relevan **dan** memiliki `eligibility_block_codes` (atau CandidateReason severity_level = `SOFT_BLOCK`) → masuk `avoid`.
   - Jika `AVOID_REQUIRES_SIGNAL=true` dan ticker tidak relevan → `excluded`.

2) **Low-quality avoid (opsional)**
   - Jika ticker relevan, tidak eligible, dan `score_total` rendah → boleh masuk `avoid` hanya jika `score_total >= AVOID_MIN_SCORE`.
   - Jika di bawah itu → `excluded`.

3) **Freshness (opsional)**
   - Jika policy menyediakan `signal_first_seen_date`/`signal_age_days` atau marker “age” lain, engine boleh menerapkan `AVOID_SIGNAL_MAX_AGE_DAYS`.
   - Jika marker terlalu tua → `excluded` (avoid hanya untuk masalah yang masih “fresh”).

---

## Group assignment order (ranked policies)

Urutan keputusan **wajib** seperti ini (tidak boleh diacak):

1) **Universe gate**
   - Jika tidak relevan → `excluded`

2) **Hard exclude**
   - Jika ada CandidateReason severity_level = `HARD_EXCLUDE` → `excluded`

3) **Avoid (blocked / not eligible)**
   - Jika tidak eligible untuk new entry (hard rules fail / block codes) → ikuti aturan “Avoid semantics” di atas.
   - Catatan: hard-rule fail **tidak boleh** otomatis jadi `watch_only`.

4) **Ranked buckets (eligible only)**
   - `top_picks`: eligible && `score_total >= top_cut`
   - `secondary`: eligible && `score_total >= SECONDARY_MIN_SCORE` (dan < top_cut)
   - `watch_only`: eligible && `score_total >= WATCH_ONLY_MIN_SCORE` (dan < secondary)
   - else → `excluded`

---

## NO_TRADE mode (monitor-only)

Policy `NO_TRADE` tidak memakai cut/ranking di dokumen ini.

Kontrak:
- Output tetap **wajib** ada untuk membedakan “mode monitor” vs “tidak ada data”.
- `groups.no_trade[]` adalah daftar monitoring (policy-defined), **bukan ranked**.
- `score_total` untuk `NO_TRADE` tidak boleh menimbulkan ilusi “kandidat terbaik”; implementasi boleh memaksa `score_total=0` atau mengabaikan score untuk display.
