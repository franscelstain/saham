# Legacy Support — Input/Output Compatibility (Contract)

Dokumen ini menjelaskan **apa saja compatibility yang masih didukung** untuk input/output watchlist yang lama, supaya:
- tidak ada “support diam-diam” yang bikin bingung,
- migrasi bisa terukur,
- kita tahu apa yang boleh dihapus kapan.

## Prinsip
1) **Contract utama** tetap `docs/watchlist/1.contract.md` + policy docs.
2) Legacy support hanya boleh:
   - menerima alias field lama → dinormalisasi ke schema baru, atau
   - menerima enum/shape lama → dimapping ke shape baru.
3) Legacy support **tidak boleh** mengubah rumus/angka LOCKED.

## Legacy inputs yang masih diterima (alias → canonical)

### Options / runtime
- `capital_total` → `capital_idr`

### Group semantics config (config/env)
- `top_pick_max` → `toppick_max`  
  Catatan: ini hanya **CAP display/selection**, bukan bagian rumus `top_cut`.

### Candidate OHLC
Beberapa path lama bisa mengirim OHLC di key berbeda. Engine menormalisasi:
- `o,h,l,c,v` → `open,high,low,close,volume_shares`
- `volume_shares` ↔ `v` (alias)

### Reasons object
Engine menerima dua bentuk berikut dan menormalisasi ke bentuk contract:
- Canonical: `{code,message,severity_level}`
- Legacy: `{code,message,severity}`

## Output
Payload contract (preopen) **tidak berubah** untuk legacy.  
Jika UI lama butuh field tambahan, itu harus lewat layer adaptor UI, bukan mengubah contract.

## Deprecation rule
Untuk menghapus 1 legacy alias:
1) Buat PR PROPOSAL (catat usage dan siapa pemakai).
2) Tambahkan warning log 2 release terlebih dulu.
3) Hapus alias + update tests/fixtures.
