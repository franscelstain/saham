# Data Quality & Graceful Degradation

Dokumen ini **non‑canonical** dan hanya berisi contoh + panduan implementasi.  
Aturan yang mengikat ada di **`docs/watchlist/1.contract.md`** (lihat bagian *Data Degradation Rules*).

## Sumber Data (Pragmatis)
- OHLCV EOD: provider (mis. Yahoo) → `ticker_ohlc_daily`
- Indicators: `trade:compute-eod` → `ticker_indicators_daily`
- Status ticker: manual override (boleh bolong)
- Corporate action hint (`ca_hint`): Yahoo `events=div|split` + optional gap detection

## Contoh Kasus

### 1) Status manual tidak ada
- Input: tidak ada row status untuk BBCA pada 2026-02-10
- Output:
  - status dianggap `REGULAR`
  - `reasons[]` berisi reason object: `{code:"GL_TICKER_STATUS_DEFAULTED_REGULAR", severity_level:"WARN"}`

### 2) Yahoo tidak mengirim events
- Input: `ca_hint` null
- Output: tidak ada CA warning; kandidat tidak diblokir.

### 3) Ada split dekat trade_date (high risk gap)
- Input: `ca_hint=SPLIT`, event_date berada pada H-1/H/H+1 dari `exec_trade_date`
- Output:
  - `is_eligible_new_entry=false`
  - `reasons[]` berisi reason object: `{code:"GL_CA_SPLIT_WINDOW", severity_level:"SOFT_BLOCK"}`
  - Kandidat tetap tampil (minimal `watch_only`)

## Catatan policy overrides (contoh, non‑binding)
Policy boleh memperketat/melonggarkan selama tetap memakai `severity_level` yang sama (WARN/SOFT_BLOCK/HARD_EXCLUDE) agar anti salah tafsir.
- WEEKLY_SWING: default warning (`severity_level=WARN`), dan soft-block (`severity_level=SOFT_BLOCK`) untuk split window.
- DIVIDEND_SWING: `DIV` bisa jadi sinyal/bonus, bukan gate negatif.
- INTRADAY_LIGHT: lebih konservatif pada `SPLIT/POSSIBLE_CA`.
